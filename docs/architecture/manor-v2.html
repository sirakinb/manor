Architecture / Version 2

Your laptop controls the work.
The VPS does the work.

Manor’s Maintenance Agent uses a private development workspace on the server. You review its change and approve the exact tested release. A separate, trusted controller handles the rollout.

Implementation status: foundations merged; production integration is undergoing isolated validation. This page does not imply that the rollout is already live.

One VPS, three distinct areas

Production serves people and runs ordinary agents. The development container handles proposed code changes. The operator-installed release controller holds the limited host authority required to build, back up and replace services.

Ordinary agents

Keep doing business work

They can use their existing computers and integrations. They receive no maintenance tools, release tokens or source workspace.

Maintenance Agent

Can propose a fix

It can investigate selected evidence and edit isolated source. It cannot approve a release or run host commands.

Deployment owner

Approves what goes live

Organization-admin status is insufficient. The backend checks the current deployment-owner identity on requests and worker advances.

The current preview is a private source diff. An authenticated live application preview is a separate capability; this page does not claim that it is available.

Infrastructure, schema, dependency and native application changes require a separate operator release. They are not silently promoted through this maintenance path.

What happens if the tab closes?

Jobs, reviews and approvals remain in the database. The worker reconciles durable jobs after a restart. An interrupted arbitrary coding command is recorded as uncertain and is not blindly replayed. Isolated workspaces have independent cleanup limits.

Approval is the start of a guarded rollout

The coding agent is finished by this point. The operator-installed controller owns these actions; candidate source cannot replace its Docker policy, credentials or host commands.

Before a switch fails

A drain or backup failure leaves the current image in place. The controller resumes paused producers and reopens admission when safe.

After a switch fails

The controller restores the prior application image and checks its health. Data volumes are retained; rollback is not a database rewind.

The controller restarts

The durable journal records the unfinished phase. Recovery is explicit. A missing response is never treated as a successful deployment.

Maintenance commits remain private on the VPS unless separately reviewed and published. Keeping them synchronized with the public main branch is a deliberate Git step; deploying a private fix does not automatically create a public PR.

No development root

Code runs as a non-root user. The development container does not receive the host Docker socket, production credentials or production data mounts.

One heavy job at a time

The host checks free memory and disk before work begins. A build must preserve operating headroom and retained rollback images.
